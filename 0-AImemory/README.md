# 0-AImemory

**0.1** This folder is the working folder for any AI, meaning any artificial-intelligence agent, that works on the project.

**0.2** The Library is the shared set of notes on rules and formats that the project points at. Its `Method/Folder_Structure.md` sets out this folder's place in the project's layout. `RULES.md`, in this folder, says where the Library is.

**0.3** The folder exists to enforce one rule: nothing specific to the project is stored anywhere outside the project's own tree, including an AI's own external memory. The Library states the rule in `Method/Folder_Structure.md`, under the entry for `0-AImemory`, and in `Method/Cross_Functional_Team.md`, under "Rules the team holds".

**0.4** The folder holds the AIs' working files, together with three files the team keeps. `RULES.md` is the rules file, which an AI reads first in every session. `HANDOFF.md` is the resume file, from which an AI with no conversation behind it continues the work. `BINDER.md` is the policy binder, the numbered record of the policies and decisions in force. The Library's `Method/Cross_Functional_Team.md` defines all three under "Terms".

**0.5** The folder is not a home for project content that has a place of its own. What is being built, and why, belongs in `Objective.md` at the project root. A design belongs in `1-Design/`. A backlog item belongs in `9-Backlog/`.

**0.6** What an AI may do in this folder without asking is stated in the Library's `Method/Folder_Structure.md`, under the entry for `0-AImemory`. `RULES.md` says how the project applies it.
